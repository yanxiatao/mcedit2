# MCEdit2 Rust 重写范围与差异验收

约定范围的 Rust 重写与迁移已完成。唯一 `mcedit2` 入口提供桌面、命令行与内部插件宿主，原版实际工具与文档入口的迁移范围见下表。工作区统一构建和 25 个现有类别全部通过，真实桌面与存档读回记录见 [PROGRESS.md](PROGRESS.md)，验证方法和日志见 [TESTING.md](TESTING.md)。

## 大结构与任务预算

完整结构导入、选区导出、原稿格式转换和放置预览使用编辑面板的任务预算，默认 256 MiB；完整克隆 / 移动使用其面板中的独立任务预算。预算估算新增密集状态、源解码、附加载荷、证明、重采样和候选构建，不代表已有会话、全部历史或整个进程的硬内存上限。按区块捕获后仍写回 Y/Z/X 密集索引，方块实体保留原始 Compound，实体树保留完整载荷，群系继续遵守整列 / 四格规则。

五种格式和结构重采样不再以 4096 格作为体积上限，按工作预算检查；文件和 Compound 的独立安全上限为 64 MiB，NBT 深度 64、节点 100 万等既有解析限制保持有效。格式无法表达的稀疏网格、群系、未知字段或版本 / 注册表转换正常报错，不省略载荷。剪贴板放大、镜像、XYZ 旋转、重复克隆及重叠移动继续使用冻结来源和原来的 UUID 策略；取消和后段失败不发布部分正式会话。

## 插件使用与边界

1. 开发与本机测试复用 `target/debug/mcedit2`；默认打开 GUI，`--inspect` 运行只读检查，内部 `--plugin-host` 由同一程序以独立进程执行。Windows 发布包只需一个产品程序及示例插件；本次没有触发发布构建或远程打包。
2. 在高级工具的“导入导出与保存”中选择插件目录，扫描后选择插件并显式启用。扫描不执行 Python 源码。
3. 加载命令后输入选项，使用当前编辑选区运行。结果显示日志和原生编辑预览；只有点击暂存才进入可撤销的内存编辑组，保存仍走现有确认路径。
4. 禁用、重新加载、改变选区 / 选项 / 任务预算 / 超时或切换世界会使在途结果失效。源文件摘要变化、源选区变化、异常、越界、超时或取消均不应用结果。

运行时执行的是 Python 3，不自动改写 Python 2 语法。支持的旧接口包括命令注册、选区坐标、逐方块读写、条件填充、旧数字 ID 与 metadata，以及常用命令选项。`QMessageBox` 的信息/警告/错误映射为编辑器插件日志；其他 Qt 控件和 NumPy 不冒充可用。旧插件若依赖这些接口，需按实际需求迁移。

## 保存组与历史 NBT

当前维度的保存预览可列出多个 Region，保留每个文件的源摘要与精确候选镜像。确认时重新生成并逐项比较预览。多文件组先完整预检，再记录整组日志，并按已有单文件事务进行替换；出错时记录并传递原始错误，保留活动日志和备份，等待显式选择解决方向。活动日志会阻止单独修改组内 Region 的恢复状态。

组恢复先检查所有文件的当前摘要及原始备份，发现外部修改时保持其他文件不变。输入 `FINALIZE_GROUP` 或 `ROLLBACK_GROUP` 解决保存组。一旦开始最终确认或回滚，后续恢复须继续相同方向。备份与终态记录都保留，不自动删除。单组最多 64 个 Region、候选总计 1 GiB，单 Region/备份最多 256 MiB。

原版 1.8 样本包含 Region 压缩流内的一层 GZip，原版 `nbt.load` 会处理它。Rust 读取与候选写回现已显式识别这一编码，验证 GZip 解码结果，并保留内层 GZip 及其头部元数据。损坏编码或更多层嵌套直接报错。回归测试覆盖真实样本读取、改动、再编码与原始文件不变。
